# Wildberries 裂变 Skill 全面检查与修复

核查日期：2026-10-10（US/Pacific）。修改位于 Codex 与 Antigravity 共用的 Skill 目录。

## 结论

本轮发现并修复了任务控制连接、聊天隔离、凭据处理、收件可靠性、断点恢复、图片发送以及独立 WB 发布模块中的问题。网关已部署，本机常驻执行服务已重启。

不能把此前故障统一归因于 WB API。原任务的中断日志指向连接超时和续租；这次实测另发现本机系统代理返回旧任务字段，直连则返回新版。当前 WB 官方卡片接口可读取10张目标商品卡，每张有8张图片记录。

## 已修复

| 问题 | 修复结果 |
| --- | --- |
| 系统代理路径返回旧任务快照，控制连接会超时 | 查询、领取、续租及原图网关请求默认直连；JSON禁止缓存。原生生成网络独立配置。 |
| 同一用户不同聊天共享最近任务 | 按发送人和聊天共同定位；旧记录补建聊天索引，补图、资料和重试不跨聊天。 |
| 店铺令牌复制进任务对象；保存凭据后错误承诺自动上架 | 凭据独立保存，任务响应脱敏并清理历史副本；保存成功不再声称已验证权限或将自动上架。修正凭据读取请求方法。 |
| 飞书确认收件后后台失败，缺少可靠重试 | 先持久保存事件再确认；事件独占领取、重试最多5次，完成后删除原消息内容；重复输入不会覆盖新资料或重新启动已完成任务。 |
| 多执行器心跳覆盖能力；无生成能力的服务可能抢任务 | 分别记录执行器，汇总可用生成能力；无生成配置的执行器不领取；失效租约不能刷新健康状态。 |
| 多链接时只取第一个，源文件缓存损坏导致失败 | 拒绝不同商品混合输入；损坏/空缓存重新读取，公开资料失败时仍可用提供的真实原图，CDN可独立补救；保留维护者确认的品牌等事实。 |
| 缓存结果绕过事实审查；写到一半的包堵塞后续重试 | 恢复时核验商品编号和事实；新缓存原子写入，暂存资产完整校验后整体提交。核验图片SHA-256、manifest及ZIP。 |
| 图片断点缺少原图/文案关联 | 已接受图片绑定原图、事实、场景、图像校验值和审查结果，不仅判断文件存在。多账号登录明确选择，不静默换账号。 |
| 旧发送回执可能被用于另一聊天/另一版成品 | 回执绑定任务、聊天和成品版本；每次上传后、真正发送前再核验租约；有歧义的历史回执先核查，避免盲目重发。 |
| WB辅助模块把Base64交给链接接口、截断标题、漏图仍返回成功 | 本地图片走官方multipart文件接口；校验全部图片、正数包装参数、唯一条码和60字符标题，不改变同款物理属性；检查业务错误，建卡及媒体读回后才返回结果。 |
| 上架模块缺少防重复写入措施 | 显式发布授权、已核验事实和私有断点齐备才执行；断点绑定载荷、图片和凭据；不确定建卡结果时读回核查，不自动重复建卡。 |
| 文档宣称的数量支持与自动流程不一致 | 明确飞书自动流程固定10套；手工Agent流程和通用导出器支持指定数量；图文完成与店铺可售分别验收。 |

WB媒体格式依据：[WB官方商品与媒体API文档](https://dev.wildberries.ru/en/openapi/work-with-products)。`media/save`接收公开URL，`media/file`接收multipart文件；HTTP 200仍需检查业务错误和媒体记录。
