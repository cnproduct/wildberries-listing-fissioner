# 批次混淆与生成模型 404（2026-10-13）

## 已核实事实

- 飞书原消息 om_x100b63ee797a6c84b1aea9e36397371 内容为“WB 货号 1879785812 继续上架”，旧回复却创建了图文生成任务。
- 该任务的私有 generator.err.log 最后一行是 Native generation HTTP 404。它与此前 om_x100b63f4aa3d14a0b296c89eebe9ba6 的第 3 张质量审查失败不是同一批。
- 飞书后来“重试”的回复声称已交付，未标明实际请求编号。检查时新失败请求已不在当前列表，旧任务仍 ready；旧任务压缩包消息可读。代码曾支持物理删除任务并让指针退回旧批次，按货号查找还优先选择 ready。无法从现存记录确定谁移除了任务，不作归责。
- 同一账号、同一 sandbox 生成节点的可用目录不再包含 gemini-3.7-flash-high；旧适配器固定请求它，实测 404。目录包含 gemini-3.8-flash-high 和 gemini-3.1-flash-image。生产节点目录不同，不能把另一个节点的可用模型当作当前节点可用。

## 修复

1. 同商品按最新请求定位，不优先选旧 ready；指定编号缺失时明确找不到，不回退；编号查询严格检查当前聊天。
2. 重试回复显示货号与请求编号，ready 还需交付字段才能称已交付；协调器拒绝直接重试 ready 防止竞态重复发送。
3. 禁止物理删除任务历史。提供鉴权、只可创建缺失 failed 记录的维护恢复接口；只接收有限身份字段，禁止覆盖现有任务或入执行队列。恢复依据必须是重新读取的原飞书消息。
4. 生成前读取同节点模型目录，默认在已支持的文本模型名单中选择；显式指定不支持的模型直接报错，不能默默换模型。修复后 --probe 文本调用成功，图片模型仅验证目录存在，没有生成测试图片。
5. 新增 generation_model_unavailable 诊断，404 说明归属图文生成服务，提示维护服务后重试。
6. “继续上架”不创建新图文任务。旧代码只拼接“即将建卡”回复，没有真正提交发布执行任务，现改为明确没有启动发布；删除原商品必然单图、已具备每款完整图库等无证据描述。
