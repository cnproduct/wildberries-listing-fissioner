# WB / Ozon 双平台截图对比

适用于每次新制作或经用户授权重做的商品图，位于生成前的来源核验和生成后的交付审查之间。目标是保留商品本体，仅改变允许的外部场景；不是要求新背景与原背景一致。

## 1. 取得真实证据，先确认包装版本

- 分别定位 WB 和 Ozon 的实际商品链接、平台货号、选中的规格及包装版本。不能把 WB 货号直接当作 Ozon 货号，也不能仅凭同品牌搜索结果认定同款。缺少另一平台链接时可查找，但必须用实物特征、规格或可信商品资料核实对应关系；无法核实就记录缺项。
- 使用当前可用的浏览器工具打开两边商品页，保存可识别链接/货号及当前规格的页面截图，再打开图库大图并截图。用户已提供的截图可使用，标为“用户截图”，不能伪称当前在线抓取。登录拦截、页面失效或浏览器不可用要明确记录，不能用生成图、下载文件或网页 HTML 冒充页面截图。
- 同时保存实际编辑用的原图及来源。页面截图用于确认展示版本，原图用于细节对照；低清截图不能授权模型脑补微小文字。没有清晰证据的文字、容量和结构标为“无法核实”。
- 先比较两平台商品：瓶型/结构、瓶盖、颜色、Logo、标签版式、规格和销售组合。若存在不同包装、透明/有色版本或不同容量，不混合生图。用户已经明确选择版本则沿用该决定，并记录另一平台的差异；没有决定时先展示差异并请求选择。
- 区分包装上的真实标签与页面广告。红色标签若属于瓶身就必须保留；商品外的促销横幅可按需求去掉。单瓶容量、套装总量、件数分别记录，不能把页面总量直接印到瓶身上。

## 2. 逐张生成、逐张保存对照

每张成品使用已确定的真实底图编辑。保持源图只读；返工输出新文件，不覆盖证据或已交付图片。保留底图、成品和各截图的 SHA-256，记录生成版本，防止拿旧审查给新图片放行。

在本批输出目录保存 `visual-review/`，内容包括：

- WB、Ozon 商品页面截图和图库大图截图，平台链接、货号、规格、截图时间和采集方式；
- 本次实际编辑底图、每张待审图片以及它们的校验值；
- 对照页：WB 原图、Ozon 原图、生成图三列并排；用浏览器打开并保存对照页截图；
- 标签、Logo、容量、瓶盖、边缘结构等局部对照。允许展示缩放，禁止美化、补字、锐化伪造原图细节；不改变证据文件；
- `review.md`，逐张逐项写明结论、差异、对应证据和下一步，不以一个笼统的 passed 代替核查。

对照页和截图只是展示证据，不能单凭“对照页已生成”认定图片一致。必须实际打开查看；可辅以模型或文字识别，但不可把识别错误自动解释为原图文字。

## 3. 核对表

每张图分别对照 WB、Ozon 和实际编辑底图，逐项标记“一致 / 不一致 / 无法核实”，并注明图片位置。

| 项目 | 必查内容 |
| --- | --- |
| 形状与比例 | 宽高关系、肩部、底部、边缘、透明度、液面、结构；不能重塑瓶型 |
| 瓶盖与配件 | 颜色、纹路、开闭状态、泵头、盒子、随附物品 |
| 品牌 | Logo 形状、颜色、字母、大小及位置；同品牌不同包装也不能混用 |
| 标签 | 红色等色块、标题、文字、字体布局、图标、插画及其位置；不能少红条或重新画管道图案 |
| 数字与规格 | 容量、单位、数量、型号、比例、时间数字；套装总量不能冒充单瓶容量 |
| 色彩与材质 | 瓶体、标签、瓶盖、液体的颜色与材质；不能借背景光改变商品颜色 |
| 件数与组合 | 实际售卖件数、每件容量、组合关系；不能复制/少画或暗示赠品 |
| 机位与遮挡 | 保持底图角度，商品和关键标签可见；不能生成未见部位或用道具遮住差异 |
| 文案对应 | 标题和描述与原商品及实际图片一致，不增加原图未证实的功能或数字 |

## 4. 判定与返工

- **未发现可见差异**：对应关系、包装版本和必查项都有清晰证据，逐项一致。这个结论不等于像素完全相同，也不等于 WB 平台审核通过。
- **不一致，需返工**：列出具体位置和变化，保留失败图及证据。最多按原底图纠正三次；仍不一致则停止交付该图。不得通过降清晰度、遮挡、模糊数字、放宽阈值或重复询问审查模型来获得通过。
- **待核实**：截图缺失、单平台无法访问、款式对应不确定或标签不可读。可以准备带状态标识的审查材料，但不得作为合格成品发送或上架。
- **来源冲突**：两平台的商品版本不同，先列出差异；用户已选定版本时可单独写“与指定版本未发现可见差异”，同时写“另一平台包装不同，双平台一致性未通过”。不能同时声称匹配两套互相矛盾的包装。
- **严格像素一致**：只有保留原商品像素并验证商品区域的流程才能这样表述。需确认商品区域覆盖完整主体、两图对应关系正确，再比较商品区域的实际像素；只匹配背景、空掩膜、文件数量、整图哈希或相似度阈值均不证明商品一致。纯生成式编辑无法给出该保证时应直接说明。

十张主图逐张检查；每款八图也必须八张全部检查。旧图片可以保留，但旧的单源审查不等于新双平台审查；再次用于新交付前补做检查，不自动重生成或重发历史成品。

## 5. 记录格式与执行边界

`review.md` 至少包含：任务/货号与批次、WB/Ozon 链接及各自货号、选中规格与包装、用户已确认的版本、截图路径与时间、底图与成品校验值；每张图的九项核对结果和定位；来源冲突/未核实事项；最终结论、检查人或模型、检查时间。

本规则由调用 Skill 的 Agent 使用可用浏览器和图像查看工具执行。当前后台原生适配器只接收已有原图并进行单源模型审查，尚不具备 WB/Ozon 自动页面截图和逐像素商品区域比较能力。不能将此文档更新宣传为后台已自动执行双平台检查。使用无人值守后台生成的图片时，必须按本规则完成补充核查后才称为合格；若要自动阻止后台发送，则需另接截图采集与审查状态校验，不能只增加一句提示词代替。
